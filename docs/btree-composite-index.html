Indexes and performanceIndex 與效能

Composite indexes: equality first, range last複合 index：等值在前，範圍在後

An index is a sorted phone book. A two-column index sorts by the first column, then by the second within each first-column value. Index 就像一本排好序的電話簿。兩個欄位的 index，先依第一欄排序，第一欄相同的，再依第二欄排序。

The query要加速的查詢

WHERE customer_id = ? AND status = ? AND created_at >= ?
ORDER BY created_at
LIMIT 50

Right order: (customer_id, status, created_at)正確順序：(customer_id, status, created_at)

The two equality columns narrow it to one slice, and that slice is already ordered by created_at. The database reads 50 entries and stops, with no sorting. (status, customer_id, created_at) works just as well. 兩個等值欄位把範圍縮到一小段，而那一段本來就依 created_at 排好了。資料庫讀 50 筆就停，不用排序。(status, customer_id, created_at) 也一樣好。

Wrong order: range first錯誤順序：範圍放前面

After a range column, the columns to its right can't narrow the scan anymore. "Put the most selective column first" is a myth: order columns by how the query uses them. 一旦遇到範圍欄位，它右邊的欄位就無法再縮小掃描範圍。「選擇性最高的欄位放最前面」是迷思：欄位順序要看查詢怎麼使用它們。
