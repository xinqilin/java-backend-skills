N+1 queriesN+1 查詢

You ask for 100 orders. You get 1 query for the orders, plus 1 more for each order's customer. 你要 100 筆訂單。結果是 1 次查訂單，再加上每筆訂單各查 1 次客戶。

One page, 101 trips to the database一個頁面，跑資料庫 101 趟

for (Order o : orderRepository.findByStatus(PENDING)) {
    o.getCustomer().getName();   // lazy: one query per order
}

Three fixes三種解法

FetchType.EAGER is not a fix: it applies to every query that touches the entity and can't be turned off. FetchType.EAGER 不算解法：它會套用在每個碰到這個 entity 的查詢，而且關不掉。

The pagination trap (depends on your version)分頁陷阱（要看版本）

Works on every version: page the ids first, then fetch those orders with their items. Also set hibernate.query.fail_on_pagination_over_collection_fetch=true so an in-memory page becomes an error instead of a surprise. 所有版本都適用的寫法：先分頁取 id，再用這些 id 把訂單連同明細一起撈出來。另外設定 hibernate.query.fail_on_pagination_over_collection_fetch=true，讓記憶體分頁直接報錯，而不是默默發生。
