JPA and HibernateJPA 與 Hibernate

The persistence contextPersistence context

Inside a transaction, Hibernate keeps a notebook of every entity it loaded. Change an object, and the notebook writes the SQL for you. 在交易裡，Hibernate 會把它載入的每個 entity 記在一本筆記本裡。你一改物件，筆記本就幫你寫好 SQL。

Load, change, flush載入、修改、flush

No save() needed: comparing the object with its snapshot is called dirty checking. It costs memory and time for every entity loaded, even unchanged ones. 不需要呼叫 save()：把物件和快照比對，就叫 dirty checking。每個載入的 entity 都要花記憶體和時間，就算沒改也一樣。

What readOnly = true really doesreadOnly = true 實際做了什麼

A good optimization for read paths, not a security wall: whether the database itself refuses writes depends on the driver. 對讀取路徑是很好的優化，但不是安全防線：資料庫本身會不會拒絕寫入，要看 driver。

Bulk updates skip the notebook批次更新會繞過筆記本

A @Modifying JPQL update writes straight to the database. Entities already in the notebook keep their old values. Use clearAutomatically = true, or don't load them first. @Modifying 的 JPQL update 會直接寫進資料庫，已經記在筆記本裡的 entity 還是舊值。請用 clearAutomatically = true，或者不要先把它們載入。

save() is persist or mergesave() 其實是 persist 或 merge

Spring Data decides "new" by a null version or null id. If you assign ids yourself (UUIDs), every save() merges, which runs an extra SELECT. Implement Persistable to fix it. Spring Data 用 version 或 id 是不是 null 來判斷「新的」。如果 id 是你自己給的（例如 UUID），每次 save() 都會走 merge，多跑一次 SELECT。實作 Persistable 就能解決。
