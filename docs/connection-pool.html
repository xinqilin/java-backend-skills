Connection pool sizingConnection pool 大小

A database can only work on a few things at once. More connections don't add workers; they add a queue inside the database. 資料庫一次只能專心處理少數幾件事。增加連線不會多出工人，只會在資料庫裡面多出一條排隊的隊伍。

Small pool, short line at the door小 pool，門口排短隊

Starting point from HikariCP's guide: (core_count × 2) + effective_spindle_count, using the database server's cores. Then load-test around it. HikariCP's default is 10, and it recommends a fixed-size pool (leave minimum-idle unset). HikariCP 建議的起點：(core_count × 2) + effective_spindle_count，core 數用的是資料庫主機的。之後再壓測微調。HikariCP 預設是 10，並建議固定大小（不要設定 minimum-idle）。

"Connection not available" is usually not a size problem「拿不到連線」通常不是 pool 太小

Virtual threads: the pool becomes the gateVirtual thread：pool 變成唯一的閘門

With spring.threads.virtual.enabled=true, threads are cheap but connections are not. Thousands of virtual threads can wait for 10 connections, and connection-timeout (30 s by default) decides who fails. Size the pool for the database, not for the number of threads. 開啟 spring.threads.virtual.enabled=true 之後，thread 很便宜，連線卻沒有。上千個 virtual thread 可能在等 10 條連線，由 connection-timeout（預設 30 秒）決定誰失敗。pool 的大小要依資料庫來訂，而不是依 thread 數量。
